# Design

## Context

見 proposal.md - Why。現有 Google Sheets adapter 在無 `gid` 時偏好名為「學習單」的分頁，`parse_guided_notes` 也固定讀取同名分頁。題目模型及 SQLite `questions` 僅保存題號；學生加入時透過 `/api/rooms/{room_id}/questions` 取得題目欄位，WebSocket 的階段事件目前只傳送狀態。

## Goals / Non-Goals

**Goals:**

- 依明確 `gid` 或最新符合格式分頁建立房間，且保留答案格原始座標及試算表分頁名稱供回填。
- 保存每列題目文字及其答案標記，支援同題多列內容按序呈現。
- 等待階段不透過學生題目 API 洩漏題目文字；搶答啟動後再載入並顯示。
- 以加法遷移保留既有房間、答案及回填資料。

**Non-Goals:**

- 不變更 Google Service Account scope、分享權限或原表回填仲裁方式。
- 不改變教師進度板、投影畫面或搶答排名與題組規則。
- 不支援缺少可辨識題號或答案格的任意工作表。

## Decisions

1. **用分頁順序定義最新分頁。** Google Sheets 回傳的 `sheets` 順序對應試算表分頁排列。指定 `gid` 時只檢查指定分頁；未指定時由排列最後一個分頁往前檢查，選擇第一個符合題號與答案格格式者。這比以名稱或第一個分頁作預設更符合老師把新題目放在最新分頁的操作；不符合格式的最新分頁會被略過。若指定 `gid` 的分頁不合格式則直接回報錯誤，不靜默改用其他分頁。

2. **讓解析器回傳逐列題目片段。** 在既有題號／答案格解析結果中加入題目欄文字及其答案標記、原列順序。題目欄可不存在或空白；若同題多列，保存各列而不串成失去標記關係的單一字串。房間建立時仍以題號及答案格作為有效格式判斷。

3. **以獨立資料表保存題目片段。** 新增 `question_prompts` 表，保存題目 ID、來源列順序、答案標記及文字，避免把多列資料壓成單欄字串。`questions` 與答案提交表結構不變；舊房間沒有 prompt rows 時 API 回傳空內容，既有房間仍可參賽及回填。

4. **按房間階段回傳學生可見內容。** 等待中的 questions API 保留題號與答案格，但不附題目片段；房間進入 active 後才附帶片段。學生收到 `phase.changed: active` 時重新抓取 questions 並重繪題目卡片，再啟用輸入。加入 active 房間的學生第一次抓取即可取得題目。這避免只用 CSS 隱藏而仍可在等待時透過 API 讀取題目。

5. **用安全文字節點呈現並保留標記。** 前端以 `textContent` 建立題目列，依來源順序逐行顯示；有答案標記時同列顯示標記，沒有題目文字時維持既有題號與空格顯示。避免以來源題目文字當作 HTML。

6. **README 具體指引分享權限。** 老師從 Google Cloud Console 的 Service Account 詳情或其金鑰檔的 `client_email` 欄位取得服務帳號 email，將試算表分享給該地址。讀取建房需檢視權限；要回填則需編輯權限。文件只說明欄位名稱，不複製任何 JSON 憑證內容。

## Risks / Trade-offs

- [分頁排列不等於建立時間] → 文件將「最新」定義為 Google Sheets 顯示順序中最右側；老師新增題目後若要自動選取，需將該題目分頁置於最右側，或明確提供 `gid`。
- [多個符合格式的分頁可能是舊題目] → 未指定 `gid` 時選最右側符合分頁，README 說明如何將當次題目表移至最右側；明確 `gid` 可固定指定來源。
- [舊房間沒有題目文字] → 遷移只建立新表，不回填或重寫舊房間；API 以空題目片段相容舊資料。
- [等待階段內容洩漏] → 題目文字在伺服器的學生題目回應中按房間狀態篩除，不依賴前端隱藏。

## Migration Plan

1. 新增版本化 SQLite migration 建立 `question_prompts` 表；不刪除或重寫既有欄位及資料。
2. 部署支援新遷移的 Python 服務、學生頁與 README。啟動時套用遷移後，舊房間 prompt list 為空，新房間保存匯入文字。
3. 回滾應用程式版本時保留新增資料表；舊程式不讀取該表且既有 schema 仍可用。若資料庫已進入新版本，不手動刪表，以免丟失新題目資料。
